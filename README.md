# CyberQuest

**Учись кибербезопасности через практические ситуации**

CyberQuest — учебная **2D-игра** для студентов. Игрок ходит по карте учебного центра, подходит к
терминалам миссий и проходит вымышленные ситуации (письма, сообщения, системные уведомления),
принимает решения, видит смоделированные последствия и получает объяснения с практическими
рекомендациями. Приложение работает локально и не взаимодействует с реальными аккаунтами, сетями
или сайтами. Все адреса используют зарезервированные домены (`.example`, `.test`) и показываются
как неактивный текст.

## Возможности

- 2D top-down карта учебного центра (WASD / стрелки / клик по карте, E — взаимодействие).
- Шесть терминалов-миссий: «Подозрительное письмо», «Защита аккаунта», «Неожиданное вложение»,
  «Обновление системы», «Резервная копия», «Работа с данными».
- В каждой миссии 4 оцениваемых решения и развилка: рискованный выбор ведёт к сцене восстановления,
  предпочтительный — к сцене проверки; затем ветви сходятся.
- Ответ фиксируется после нажатия «Ответить»; повторная отправка не учитывается дважды.
- Попытку можно завершить досрочно (помечается как незавершённая) и продолжить после перезагрузки страницы.
- Итоги миссии: баллы, верные решения, процент, решения для повторения с объяснениями.
- Вкладка «Прогресс»: статистика, последний и лучший результат по миссиям, история, разбор попыток,
  достижения, экспорт в CSV (UTF-8 с BOM) и автономный HTML-отчёт.
- Демонстрационный режим: попытки помечаются отдельно и не входят в статистику; есть подсказка ведущему.

## Установка и запуск

Требуется Python 3.11 или новее.

### Windows (PowerShell)

```powershell
cd CyberQuest
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

Если PowerShell запрещает запуск скриптов, выполните один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или активируйте окружение из `cmd`:
`.venv\Scripts\activate.bat`.

### macOS / Linux

```bash
cd CyberQuest
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`. База данных создаётся автоматически в
`data/cyberquest.db`. Другой путь можно задать переменной окружения `CYBERQUEST_DB`.

### Тесты

```bash
python -m pytest -q
```

Тесты используют только локальное содержимое и временную базу данных; сеть не нужна.

## Структура

| Файл | Назначение |
|---|---|
| `app.py` | Интерфейс Streamlit (вкладки, 2D-карта, сцены, действия) |
| `game_engine.py` | Загрузка и проверка JSON, переходы между сценами, состояние попытки |
| `game_view.py` | 2D canvas-компонент: ходьба, коллизии, терминалы |
| `scoring.py` | Правила начисления баллов |
| `database.py` | SQLite: попытки, решения, агрегаты прогресса |
| `achievements.py` | Достижения по сохранённым результатам |
| `reporting.py` | Экспорт CSV и HTML с экранированием |
| `content/missions.json` | Содержимое миссий (версия содержимого — поле `content_version`) |
| `content/world.json` | Карта 2D-мира и терминалы миссий |
| `content/references.json` | Образовательные источники |

### Формат сцены

- `decision` — оцениваемое решение: `situation`, необязательный `artifact` (письмо/сообщение/уведомление),
  3–4 варианта `options` (у каждого `consequence` и `next`), ровно один `preferred`, `explanation`,
  `recommendation`, `reference_id`.
- `recovery` / `verification` — неоцениваемые сцены разбора с полями `title`, `situation`, `steps`, `next`.
- `next: null` завершает миссию.

При загрузке содержимое проверяется: уникальность ID, существование сцен и источников, ровно один
предпочтительный ответ, отсутствие циклов и недостижимых сцен, не менее четырёх решений на любом пути.

## Правила оценки

- Предпочтительный ответ — 10 баллов, другой — 0 баллов, отрицательных баллов нет.
- Максимум = 10 × число решений, которые действительно встретились в попытке.
- Сцены восстановления и проверки не оцениваются, поэтому ветвление не меняет максимум.
- Скорость ответа не учитывается.
- Результат отражает выполнение заданий этой игры и не является профессиональной квалификацией.

## Образовательные источники

Доступность всех ссылок из `content/references.json` проверена 12.10.2026 (HTTP 200): материалы
CISA (Secure Our World), NCSC (Великобритания), NIST SP 800-63B и ICO. Содержание рекомендаций в игре
сформулировано по этим материалам в упрощённом виде; дословного соответствия нет. Рекомендуется
перед выступлением повторно открыть ссылки.

## Исследовательская гипотеза

«Ситуационные задания с объяснением последствий могут помочь учащимся выбирать более безопасные
действия в типичных цифровых ситуациях.»

Гипотеза **не проверялась**; данных об участниках, ответах или эффекте обучения нет.

### Возможный план исследования

1. **Предварительная оценка.** Короткий тест (8–12 ситуаций), не совпадающий с миссиями игры.
2. **Обучение.** Участники проходят шесть миссий в CyberQuest.
3. **Итоговая оценка.** Отдельный сопоставимый тест: те же темы и сложность, но другие ситуации
   (вариант Б), чтобы не измерять запоминание конкретных вопросов.
4. **Фиксация результатов.** Записываются фактические баллы до и после, время между тестами, число
   прохождений игры. Данные обезличиваются.
5. **Обсуждение ограничений.**
   - Эффект практики: повторное тестирование само по себе может повышать результат.
   - Без контрольной группы (например, чтение памятки вместо игры) нельзя приписать изменения именно игре.
   - Малая выборка и самоотбор участников ограничивают обобщение.
   - Тест измеряет выбор в учебной ситуации, а не реальное поведение.
   - Повторные баллы в миссиях не являются доказательством улучшения реальной кибербезопасности.

## Ограничения

- Сценарии упрощены и вымышлены; реальные ситуации содержат больше неопределённости.
- Выбор из готовых вариантов проще, чем самостоятельное распознавание угрозы.
- Один локальный профиль без регистрации; данные хранятся только на этом компьютере.
- Игра не заменяет инструкции и политики безопасности конкретной организации.
